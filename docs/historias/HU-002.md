# HU-002 — Capturar los ensayes de un lote

**Como** capturista de ERSA **quiero** capturar en el sistema los ensayes de cada lote, junto con otros capturistas, y enviarlos cuando estén completos **para** que los resultados lleguen «por sistema» y no en un Excel que se transcribe y se cambia sin aviso (RF-036; sesión 1, 00:12:51).

- **Requisitos:** RF-014, RF-020, RF-036, RF-039, RF-040, RF-043, RF-045, RF-047, RF-048
- **Por qué esa prioridad:** Es el caso principal: las pérdidas vienen de errores al transcribir lo que reporta ERSA (sesión 1, 00:11:17).
- **Depende de:** HU-001, HU-005 (los elementos salen del extracto), P-023 (oro y plata ajustados), P-048 (fecha estimada)

**Criterios de aceptación (de negocio):**
- [ ] Solo aparecen para capturar los elementos que el extracto vigente marca para esa unidad y producto, en el orden del extracto.
- [ ] Oro y plata se capturan normales y ajustados.
- [ ] Cada capturista entra con su propio usuario y puede capturar cualquier elemento; al guardar queda registrado quién capturó cada elemento y cuándo.
- [ ] Varios capturistas pueden guardar partes del mismo lote; el lote no se puede enviar a revisión hasta que todos los elementos estén capturados.
- [ ] Cada lote lleva su tipo de muestra (original, primer o segundo remuestreo) y una fecha estimada de entrega de resultados.
- [ ] El capturista no ve los ensayes de la mina ni qué elementos son pagables o castigables, y el sistema no rechaza un valor por estar fuera de un rango esperado.

**Casos de abuso:** Un capturista intenta modificar un lote ya enviado, ver los ensayes de la mina o del intercambio, o capturar con el usuario de otra persona: no puede. Un texto con código en un campo de captura se guarda como texto y no se ejecuta.
